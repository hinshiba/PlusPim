# アセンブラ

PlusPim のアセンブラ(前処理系)の現状の仕様を示す．
テスト仕様は [アセンブラ レベルテスト仕様](tests/assembler/assembler_tests.md) を参照する．
命令と指令の対応状況は [命令 対応状況チェックリスト](instructions.md) を参照する．

## 処理の流れ

ファイルごとに `ParsedProgram` が次の順で処理する．

- 前処理: 各行からコメントを除去してトリムし，空行を捨て，セグメントごとに振り分ける
- パス1: テキスト系セグメントの各行を一度だけ解析し，展開後の命令数を確定する．ラベルには確定した命令数で数えたアドレスを割り当てる．続いて `.data` を配置し，データラベルを登録する
- パス2: 完成したシンボルテーブルを使い，`la` のラベルを解決する．パス2で行が増減することはない

複数ファイルは `ParsedPrograms` が指定順に連結する．

## 行の扱い

- `#` 以降はコメントとして除去する．ただし `"` で囲まれた文字列中の `#` は除去しない
- 前後の空白を除去し，空行は無視する
- 命令の `SourceLine` はファイル上の1始まりの行番号である．空行とコメント行も数える

## セグメント

| 指令     | 開始アドレス | 内容                       |
| -------- | ------------ | -------------------------- |
| `.text`  | `0x00400000` | ユーザーの命令             |
| `.ktext` | `0x80000180` | カーネルの命令(例外ハンドラ) |
| `.data`  | `0x10000000` | データ                     |

- 指令は行全体が一致した場合のみ認識する．大文字小文字は区別しない
- 最初の指令より前の行は警告を出してテキストセグメントとして扱う
- 同じセグメントに何度切り替えても，前回の続きに配置する

## ラベル

- 空白を含まず `:` で終わる行をラベルとする．インデントしてもよく，名前に `$` を含んでもよい
- テキスト系のラベルは，直後の命令のアドレスになる
- データラベルは，直後に配置される実データの先頭(整列後)のアドレスになる
- 同名のラベルは警告を出して後の定義で上書きする．データラベルはテキストのラベルより後に登録される
- シンボルテーブルはファイルごとに持つ．分岐とジャンプのラベルは実行時に，実行中の命令が属するファイルのシンボルテーブルで解決する
- 未定義ラベルへの分岐とジャンプは実行時に `0x00000000` へ飛ぶ．`la` の未定義ラベルはエラーになり，読み込みが失敗する

## 命令の書式

- `ニーモニック オペランド`．ニーモニックとオペランドの間は空白(スペースまたはタブ)で区切る
- オペランドは `,` で区切り，`,` の後にのみ空白を置ける
- ニーモニックは大文字小文字を区別しない．レジスタ名は区別する
- テキストセグメント中の `.` で始まる行(`.align` など)は警告を出して無視する

### レジスタ

- `$` に続けて名前(`$zero`，`$at`，`$v0`-`$v1`，`$a0`-`$a3`，`$t0`-`$t9`，`$s0`-`$s7`，`$k0`-`$k1`，`$gp`，`$sp`，`$fp`，`$ra`)か番号(`$0`-`$31`)を書く
- 名前は小文字のみ受け付ける(`$T0` は不可)．番号は先頭に0を付けない(`$08` は不可)．`$32` 以上は不可
- `mfc0`/`mtc0` の CP0 レジスタは番号(`$0`-`$31`)のみ受け付ける

### 16bit 即値

| 形式     | 範囲                | 例                |
| -------- | ------------------- | ----------------- |
| 10進     | `0` から `65535`    | `100`，`65535`    |
| 負の10進 | `-32768` から `-1`  | `-4`              |
| 16進     | `0x0` から `0xFFFF` | `0xff`，`0X10`    |
| 負の16進 | `-0x8000` から `-0x1` | `-0x4`          |

- 先頭に符号(`+`/`-`)を付けられる．10進は10桁まで，16進は `0x` の後に8桁まで書ける
- 符号付きか符号なしかは命令が解釈する(`65535` と `-1` は同じビット列)
- メモリオペランドは `offset($rs)` で，`offset` は16bit即値である．`offset` は省略でき(`($sp)` は `0($sp)` と同じ)，括弧の内側に空白を置ける

## 疑似命令

| 疑似命令           | 展開                                                         | 命令数 |
| ------------------ | ------------------------------------------------------------ | ------ |
| `nop`              | `sll $zero, $zero, 0`                                        | 1      |
| `move $rd, $rs`    | `addu $rd, $rs, $zero`                                       | 1      |
| `li $rt, imm`      | 上位16bitが0なら `ori $rt, $zero, lo16`                      | 1      |
|                    | それ以外は `lui $rt, hi16` と `ori $rt, $rt, lo16`           | 2      |
| `la $rt, label`    | `lui $rt, hi16(label)` と `ori $rt, $rt, lo16(label)`        | 2      |

- `li` の即値は32bit値(書式は16bit即値と同じ．`-2147483648` から `4294967295`)である
- 展開後の命令はすべて元の行の `SourceLine` を持つ．ステップ実行は展開後の命令単位で進む
- `nop` はオペランドを受け付けない

## データ指令

| 指令      | 引数                     | 配置                                      |
| --------- | ------------------------ | ----------------------------------------- |
| `.byte`   | `,` 区切りの10進/16進    | 1バイトずつ．下位8bitを書く               |
| `.half`   | `,` 区切りの10進/16進    | 各値の前で2バイト境界に整列し，リトルエンディアン |
| `.word`   | `,` 区切りの10進/16進    | 各値の前で4バイト境界に整列し，リトルエンディアン |
| `.ascii`  | `"..."`                  | 文字列の UTF-8 のバイト列                 |
| `.asciiz` | `"..."`                  | 文字列の UTF-8 のバイト列と NUL           |
| `.space`  | 正の10進数 `n`           | `n` バイトを確保する(メモリイメージには書かない) |
| `.align`  | `0` から `30` の `n`     | 次の配置位置を `2^n` バイト境界へ進める   |

- 文字列のエスケープは `\n`，`\t`，`\0`，`\\`，`\"` である
- 不正な値，未知の指令，`.` で始まらない行は警告を出して無視する

## 複数ファイル

- ファイルは指定順に，セグメントごとに前のファイルの末尾から続けて配置する
- データセグメントは前のファイルの末尾から整列せずに続ける
- 実行開始位置は全ファイルを指定順に探して最初に見つかった `main` である．`main` がなければ警告を出して `0x00400000` から始める
- syscall を処理するにはカーネルハンドラ(`.ktext`)を含むファイルが必要である．例は `vscode_ext/pluspim/testfolder/kseg.asm`

## 失敗時の挙動

パースできない行は捨てられ，警告ログが出る．捨てた行は命令数に数えないため，後のラベルのアドレスはずれない．

| 状況                         | ログの発生元          | メッセージ                                   |
| ---------------------------- | --------------------- | -------------------------------------------- |
| 命令行のパース失敗           | `ParsedProgram`       | `<ファイル>:<n> Line skipped (cannot parse): <行>` |
| テキスト中の未対応の指令     | `ParsedProgram`       | `<ファイル>:<n> Directive ignored (unsupported in text segment): <行>` |
| セグメント指令より前の行     | `ParsedProgram`       | `Line<n> Segment type is not specified. ...` |
| ラベルの重複                 | `ParsedProgram`       | `Duplicate label '<名前>' at line <n>. ...`  |
| `.data` 中の命令など         | `DataSegmentBuilder`  | `Unexpected data segment content: <行>`      |
| 未知のデータ指令             | `DataSegmentBuilder`  | `Unknown data directive: <指令>`             |
| データ指令の不正な値         | `DataSegmentBuilder`  | `Invalid .<指令> value: <値>` など           |
| `main` がない                | `PlusPimDbg`          | `'main' label not found. ...`                |

次の場合はエラーになる．すべてのファイルを処理した後，エラーを `Error` レベルでログに出し，`AssemblyException` を投げて読み込みを失敗させる．

| 状況                         | メッセージ                                   |
| ---------------------------- | -------------------------------------------- |
| `la` の未定義ラベル          | `<ファイル>:<n> Undefined label '<名前>'`    |
