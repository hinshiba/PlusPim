# 基本的命令の実行の振る舞い

## 検証する状態

- 汎用レジスタ32本
- 特殊なレジスタ: `HI`，`LO`，PC
- CP0の状態: (`BadVAddr`，`Status` の EXL，`Cause` の ExcCode，`EPC`)
- ランタイムの内部状態: `LastException`，`IsTerminated`，`RuntimeError`，入力バッファ(標準入力から読み込んだが消費されていない入力)，出力を待っている途中までの多バイト文字のバイト列
- デバッガの状態: コールスタックの深さ，現在のラベル
- 命令が読み書きしうる範囲のメモリ

## 共通

- 命令は`ブランチ`と`ジャンプ`を除いた PC を変更しない
- 命令は自身が PC を設定したかを処理系に報告する
  - PC を設定するのは`ブランチ`(成立・不成立とも)，`ジャンプ`，`eret` のみ
  - 例外を起こした実行は PC を設定しない
  - ランタイムエラーを起こした実行は PC を設定しない
- 書いてあること以外は変化しないことを原則とする

## 正常系(例外を起こさない系)

- `execute` で例外もランタイムエラーも発生しない
- 結果を書き込むレジスタの値が，命令の定義通りの計算結果と一致する
- `undo` で実行前の状態に戻る

## 異常系(例外が生じる系)

- `execute` で命令アドレスを含む例外をが発生する
- CP0 の EPC が命令アドレス，Cause が 例外に対応したもの，EXL が1になる
- 例外を起こす命令は CP0 と `LastException` 以外の状態を変更しない
- `BadVAddr` はアドレス例外(`AdEL`/`AdES`)でのみ実効アドレスに更新され，他の例外では変化しない
- `undo` は CP0・`LastException`・`IsTerminated` を含め実行前に戻す

## カーネルモードでの例外(二重例外)

EXL が1の状態で例外が発生した場合は二重例外とし，プログラムを終了する．

- CP0 は変化しない
- `LastException` が二重例外を示す例外になる
- `IsTerminated` が `true` になる
- 例外を起こす命令は上記以外の状態を変更しない
- `undo` で CP0・`LastException`・`IsTerminated` を含め実行前の状態に戻る

## ランタイムエラー

MIPS で未定義または PlusPim が未対応の操作は，例外ではなくランタイムエラーとする．
発生条件と検証は [ランタイムエラーの振る舞い](runtime_error_model.md) を参照する．

- ランタイムエラーを起こす命令は `RuntimeError` 以外の状態を変更しない
- `undo` で `RuntimeError` を含め実行前の状態に戻る

## 繰り返し実行

ループ内の命令は同じインスタンスが何度も実行されるため，`undo` 用の情報は実行ごとに積まれる．すべての命令について以下を1ケース以上確認する．

- 同じ命令インスタンスで，入力を変えながら `execute` を3回行う(例外・ランタイムエラーを起こす命令では，正常系と異常系を混ぜる)
- その後 `undo` を3回行い，各 `undo` の後の状態が対応する `execute` の直前の状態と一致する
