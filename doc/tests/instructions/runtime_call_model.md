# ランタイムコールの振る舞いモデル

## テストの前提

- 標準入出力はメモリ上の `IDebuggeeIO`(テストプロジェクトの `InMemoryDebuggeeIO`)を `RuntimeContext` に渡して入力を与え，出力のバイト列を検証する

## 追加のパラメータ

- 実行モード: カーネルモード / ユーザーモード
- 機能番号 `$v0`: `1`(print_int)，`4`(print_string)，`5`(read_int)，`8`(read_string)，`10`(exit)，`11`(print_char)，`12`(read_char)，未知の番号(`0`，`13` など)
- 機能ごとの引数
  - print_int: `$a0` に [values.md](values.md) の代表値・境界値(負数を含む)
  - print_string: `$a0` が空文字列，ASCII，UTF-8 の多バイト文字を含む NUL 終端文字列，不正な UTF-8 のバイト列を含む NUL 終端のバイト列を指す
  - read_int: 入力として正の数，負の数，`INT_MIN`/`INT_MAX`，範囲外の数，数値でない文字列，空行
  - print_char: `$a0` の下位1バイト(上位ビットが立っている値を含む)
  - read_char: 入力が1バイト以上ある(UTF-8 の多バイト文字，`0xFF` を含む)，入力が空(EOF)
  - read_string: `$a1` を `0`，`1`，入力長より小さい値，入力長と等しい値，入力長より大きい値にする

## 追加の検証

- ユーザーモードでの実行(異常系)
  - `CpU` 例外が発生する
  - 機能が実行されない
- print_int
  - `$a0` を符号付き10進数として出力する(`INT_MIN` は `-2147483648`)
  - `undo` は状態を変えない
- print_string
  - `$a0` から NUL の直前までのバイト列を，そのまま出力する
  - `undo` は状態を変えない
- read_int
  - `$v0` が入力を32bit符号付き整数として解釈した値になる．解釈できない入力(ASCII 以外のバイトを含む行を含む)では `0` になり，その行は消費される
  - `undo` で `$v0` が元に戻り，消費した行が入力バッファに戻る
- print_char
  - `$a0 & 0xFF` の1バイトをそのまま出力する(`0x80` 以上のバイトも1バイトのまま)
  - `undo` は状態を変えない
- read_char
  - 入力から1バイトだけを消費し，その値(`0` から `255`)が `$v0` になる．EOF では `-1`(`0xffffffff`)になり，`0xFF` のバイトとは区別される
  - `undo` で `$v0` が元に戻り，消費したバイトが入力バッファの先頭に戻る
- 入力バッファ
  - 消費されなかった入力は次の読み取り(read_int/read_char/read_string)のために残り，失われない
  - `RuntimeContext` の `PendingInput` に残るバイトを，テストの状態(`MachineState`)の `PendingInput` として検証できる
  - `undo` が戻した入力はデバッギの入力ではなく入力バッファに入るため，read 系の `undo` の前後で `PendingInput` は異なる．読める入力の全体(`PendingInput` とデバッギの入力の残り)は同じになる
- read_string
  - 入力は改行までの1行で，改行が収まるなら結果に改行を含む(SPIM/MARS と同じ)
  - `$a0` から最大 `$a1 - 1` バイトの入力と NUL を書き込む．入りきらなかった残りは次の読み取りのために残る
    - `$a1 = 1` なら NUL のみ
    - `$a1 = 0` なら何も書き込まない
  - 入力が `$a1 - 1` バイトより短い場合も C# の例外を起こさない
  - 指定領域外のメモリが変化しない
  - `$a1` が非常に大きくても，実際の入力長を超えて書き込み・保存しない
  - `undo` で書き込んだ範囲のメモリが元に戻り，消費した入力も入力バッファに戻る
- exit
  - `IsTerminated` が `true` になる
  - `undo` で `false` に戻る
- 未知の番号(カーネルモード)
  - ランタイムエラー `UnknownRuntimeCall` を発生させる([ランタイムエラーの振る舞い](runtime_error_model.md))
  - 標準入出力を使わず，`IsTerminated` も変化しない
  - カーネルモードでも二重例外にならない
