# アドレス配置の振る舞い

## 追加のパラメータ

- テキストのラベル
  - ラベルの前にある命令
    - 1命令に展開される命令
    - 2命令に展開される疑似命令
  - 連続するラベル
  - 末尾のラベル
  - テキストとカーネルテキストの交互の配置
  - ラベルの前にパースに失敗する行
    - オペランドの不足
    - 書式が不正なオペランド
    - 3オペランドの `div`
    - 未定義のラベルを取る `la`
    - 未知のニーモニック
    - ラベルを取る `li`
- データの配置
  - 前の指令のサイズ
    - `.byte`
    - `.half`
    - `.word`
  - `.align n`
    - 0
    - 範囲内
    - 範囲外(`31`，負の値)
  - 複数の値を持つ指令
  - `.space`
  - データセグメントの再開
  - 末尾のラベル
- 複数ファイル
  - 各ファイルが持つセグメント
    - データ
    - テキスト
    - カーネルテキスト
  - ファイルの順序
    - テキストを持たないファイルが先
    - `main` が複数のファイルにある
  - `main` がない
  - ラベルの参照元
    - 同じファイル
    - 別のファイル
- 行とアドレスの対応
  - 行の種類
    - 命令
    - 疑似命令
    - ラベルのみ
    - 指令
  - 命令範囲外のアドレス
  - 命令の先頭でないアドレス
  - 読み込んでいないファイル

## 追加の検証

### テキストのラベル

- ラベルのアドレスは，セグメントの先頭から，それより前の展開後の命令数 × 4 を足した値になる
  - 連続するラベルは同じアドレスになる
  - 末尾のラベルは最後の命令の次を指す
- 命令数は展開後の命令数の合計であり，`SourceLine` は疑似命令の行が展開数だけ続く
- テキストとカーネルテキストは別々に数え，それぞれ前回の続きに配置する

### パース失敗とラベルアドレス

- パースに失敗した行は命令数0であり，後続のラベルのアドレスがずれない
- [パースの振る舞い](parse_model.md) と [疑似命令展開の振る舞い](pseudo_model.md) の全入力について，`GetInstructionCount` が次と一致する
  - `TryParseAll` が成功すれば展開後の命令数
  - 失敗すれば0
- パースに失敗した行は実行されず，後続のラベルへのジャンプが正しく飛ぶ

### データの配置

- 整列
  - `.half` は2の倍数，`.word` は4の倍数のアドレスに整列する
  - `.byte` は整列しない
  - `.align n` は `2^n` の倍数に整列する
    - `.align 0` は整列しない
    - 範囲外の `n` は整列せず，`.align value out of range` の警告が出る
- 複数の値は連続して配置する
- データセグメントを再開すると，前回の続きに配置する
- `.space n` は `n` バイト分アドレスを進めて `Size` に含めるが，メモリイメージにエントリを作らない
  - 実行時に読むと `0` になる
- 末尾のラベルは最後のデータの次のアドレスを指す

### 複数ファイル

- `UserInstructionCount`，`KernelInstructionCount` は全ファイルの合計になる
- ファイルを渡した順に，各セグメントを前のファイルの続きに配置する
  - データも前のファイルの末尾から続き，整列の規則を適用する
  - テキストを持たないファイルが先でも，後のファイルのテキストのラベルは `T+0` から数える
- ラベルはファイルごとに解決する
  - 別のファイルのラベルは解決できない
  - 全ファイルを対象にした解決(`ResolveFromAll`)では，どのファイルのラベルも解決できる
- `main` が複数のファイルにあれば，先に渡したファイルの `main` から開始する
- `main` がない場合は `T+0` から開始し，`'main' label not found` の警告が出る
  - 現在のフレーム名は `<unk>` になる
- [ ] `.globl` で宣言したラベルは，別のファイルから解決できる
- [ ] 要決定: `main` の重複を警告するか

### 行とアドレスの対応

行番号は1始まりである．

- 命令の行は，その命令のアドレスと相互に対応する
  - 疑似命令の行は展開後の先頭の命令のアドレスになる
- ラベルのみの行と指令の行はアドレスを持たない
- 次の場合は対応する行がない
  - 命令範囲外のアドレス
  - 命令の先頭でないアドレス
  - 読み込んでいないファイル
  - `GetAllAddressesForFile` は読み込んでいないファイルでは空を返す
- `SetBreakpoints`
  - アドレスがある行は `Verified = true`，ない行は `Verified = false` で返す
  - 同じファイルで再度呼ぶと，そのファイルの以前のブレークポイントだけが消え，他のファイルのものは残る
