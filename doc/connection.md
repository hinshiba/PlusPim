# DAP クライアントとの接続

PlusPim はデバッグ対象の標準入出力を，利用者のターミナルへ直接つなぎます．
`print_char` などの文字符号化方式に依存する処理を，PlusPim ではなくターミナルに任せるためです．
PlusPim はデバッグ対象の入出力をバイト列のまま扱い，符号化の変換は行いません．

そのため，DAP の通信には標準入出力を使わず，TCP を用います．
デバッグモード (`--debug`) では，次のどちらか一方の接続方式を必ず指定します．

旧バージョンの `--port` と `--stdio` は廃止されました．

## `--connect <host:port>`

クライアントが先に待ち受け，PlusPim がそこへ接続しに行きます．

1. クライアントがポート 0 で待ち受け，OS が割り当てた実ポートを得る．
2. クライアントは PlusPim をターミナルで起動する．このとき `--connect 127.0.0.1:<実ポート>` を渡す．
3. PlusPim が接続する．

PlusPim は接続を1回だけ試し，再試行はしません．
5秒以内に接続できなかった場合は，標準エラー出力へメッセージを出力して終了コード 1 で終了します．
`host` には IP アドレスか DNS 名を指定できます．

VS Code 拡張はこの方式を使います．

## `--listen <host:port>`

PlusPim が待ち受け，クライアントが接続します．
ポートに 0 を指定すると，OS が割り当てた空きポートを使います．
`host` には IP アドレスか `localhost` を指定します(`localhost` は `127.0.0.1` として待ち受けます)．
最初に来た1つの接続を DAP の接続とし，以降の接続は受け付けません．

待ち受けを開始すると，実際のアドレスを標準エラー出力へ1行で通知します．

```
DAP server listening at: 127.0.0.1:<実ポート>
```

クライアントはこの行を読んで接続先を知ることができます．
`--connect` に対応していないクライアントや，PlusPim を自分で起動したくないクライアント向けの方式です．

## オプションの検証

`--debug` のとき，次の場合は標準エラー出力へメッセージを出力して終了コード 1 で終了します．

- `--connect` と `--listen` のどちらも指定されていない
- `--connect` と `--listen` の両方が指定されている
- `host:port` の書式が不正，またはポートが範囲外．IPv6 は `[::1]:4711` のように `[]` で囲む
  - `--connect` のポートは 1 から 65535
  - `--listen` のポートは 0 から 65535
- `--listen` の `host` が IP アドレスでも `localhost` でもない

## ターミナルと符号化

デバッグ対象の入出力は，PlusPim が動いているターミナルの標準入出力に，バイト列のまま出力します．

- `print_char` は `$a0` の下位1バイトをそのまま出力します．
- `print_string` は NUL までのバイト列をそのまま出力します．
- `read_char` は入力から1バイトを返します．

UTF-8 の文字列を1バイトずつ `print_char` で出した場合も，ターミナルが UTF-8 として解釈できれば正しく表示されます．
どの符号化で表示するかはターミナルの設定に依存します．
ターミナルが UTF-8 でない場合 (たとえば Windows の既定のコードページ Shift_JIS) は，UTF-8 のバイト列は文字化けします．
`--force-terminal-utf8` を指定すると，PlusPim が動いている間だけターミナルを UTF-8 に切り替えられます．

### --force-terminal-utf8

PlusPim が動いている間だけ，ターミナルが UTF-8 を使うように切り替えます．
ターミナルが UTF-8 でないと，`.utf-8z`アセンブラ指令で埋め込んだ UTF-8 のバイト列が文字化けすることへの対応オプションです．

- 現在対応しているのは Windows だけです．コンソールの出力と入力のコードページを 65001 (UTF-8) に切り替えます．
- 切り替え方法が分からない環境では，このオプションはなにも行いません．
- ターミナルの設定を元の文字符号化方式に設定を戻すことは保証されません．
- 現時点では `--debug` のときだけ有効です．
