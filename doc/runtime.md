# ランタイムドキュメント

MIPS 仕様によらない PlusPim 処理系による特別な仕様について示す．

## レジスタの初期値

プログラムの読み込み時に，次のレジスタを SPIM/MARS と同じ値に設定する．
それ以外の汎用レジスタは `0` である．

| レジスタ | 初期値       | 備考                                           |
| -------- | ------------ | ---------------------------------------------- |
| `$sp`    | `0x7FFFEFFC` | `0x80000000 - 4 - 4096`                        |
| `$gp`    | `0x10008000` | データセグメントの先頭 `0x10000000` + `0x8000` |

初期値の設定は実行の履歴に含まれないので，`StepBack` で先頭まで戻っても初期値のまま残る．

## ランタイムコール

OSや実際のハードウェアの代わりに `runtime_call!` が最終的に入出力等のシステムコールを処理する．

引数を取らず， `$v0` レジスタの値を読み込み，値に応じた処理が実行される．
ユーザーモードで実行すると `CpU` が発生する．

### 機能一覧

| `$v0` | 機能         | 引数                                 | 結果               |
| ----- | ------------ | ------------------------------------ | ------------------ |
| 1     | print_int    | `$a0`: 整数                          | なし               |
| 4     | print_string | `$a0`: NUL 終端文字列のアドレス      | なし               |
| 5     | read_int     | なし                                 | `$v0`: 読んだ整数  |
| 8     | read_string  | `$a0`: 書き込み先，`$a1`: バッファ長 | `$a0` からのメモリ |
| 10    | exit         | なし                                 | 実行が終了する     |
| 11    | print_char   | `$a0`: 文字                          | なし               |
| 12    | read_char    | なし                                 | `$v0`: 読んだ文字  |

上記以外の番号はランタイムエラーとなる．

### 出力

print_int，print_string，print_char は1つの UTF-8 のバイト列のストリームに書き込み，完成した文字から順に出力する．

- 多バイト文字の途中までのバイト列(最大3バイト)は，続きのバイトが書き込まれるまで出力されない．続きは別の機能(たとえば print_char の後の print_string)で書き込んでもよい
- 不正なバイト列は，最大の不正な部分列ごとに `U+FFFD` として出力する．たとえば `0xe3` の直後に `A` を書き込むと `U+FFFD` と `A` が出力される
- exit の時点で途中までのバイト列が残っていれば，`U+FFFD` を1つ出力する
- exit を実行せずに終了した場合(切断，ランタイムエラーなど)，途中までのバイト列は出力されない

#### print_int (1)

`$a0` を符号付き32bit整数として10進数で出力する．
`0x80000000` は `-2147483648` と出力される．

#### print_string (4)

`$a0` が指すアドレスから NUL の直前までのバイト列を UTF-8 として出力する．
バイト列は出力のストリームに書き込まれるので，前後の print_char 等と合わせて1つの文字になることがある．

#### read_int (5)

入力から改行までの1行を読み，前後の空白を許して32bit符号付き整数として解釈した値を `$v0` に書き込む．
数値でない入力，32bit の範囲外の数，空行，EOF では `$v0` は `0` になる．
解釈に失敗した場合も，読んだ1行は消費される．

#### read_string (8)

入力から改行までの1行を読み，`$a0` から最大 `$a1 - 1` バイトと NUL を書き込む．

- 改行が収まる場合は，結果に改行を含む(SPIM/MARS と同じ)
- 入りきらなかった残りは消費されず，次の読み取りで読まれる
- 入力は UTF-8 のバイト列として扱い，`$a1 - 1` バイトちょうどで切る．多バイト文字の途中で切れた場合，書き込まれなかった残りのバイトは失われず，次の読み取り(read_char，read_string など)で読まれる
- `$a1 = 1` なら NUL のみを書き込む
- `$a1 = 0` なら何も書き込まず，入力も読まない
- 入力が短い場合は，実際の入力長と NUL だけを書き込む．`$a1` が大きくても，その先のメモリは変化しない

#### exit (10)

プログラムの実行を終了する．
出力のストリームに途中までの多バイト文字が残っていれば，`U+FFFD` を1つ出力する．

#### print_char (11)

`$a0` の下位1バイトを，UTF-8 のバイトとしてそのまま出力のストリームに書き込む．
上位のビットは無視する．
UTF-8 の多バイト文字を1バイトずつ print_char で出力すると，最後のバイトを書き込んだときにその文字が出力される．
たとえば `0xe3`，`0x81`，`0x82` を順に print_char すると `あ` が出力される．
`0x80` 以上のバイトを単独で書き込むと，その文字(`U+0080` から `U+00FF`)ではなく，不正なバイト列として `U+FFFD` になる．

#### read_char (12)

入力を UTF-8 のバイト列として扱い，1バイトだけを消費してその値(`0` から `255`)を `$v0` に書き込む．
EOF では `-1`(`0xffffffff`)になる．
改行も1バイトとして読まれる．
多バイト文字は1バイトずつ読まれる．たとえば入力 `あ` は3回の read_char で `0xe3`，`0x81`，`0x82` になり，print_char でそのまま出力すると `あ` に戻る．

### 入力バッファ

read_int，read_string，read_char は入力バッファを共有する．
入力バッファは標準入力から読み込んだ入力を UTF-8 のバイト列として持つ．
ある読み取りで消費されなかった入力は失われず，次の読み取りで先頭から読まれる．
たとえば入力 `ab\n` に対して read_char を行うと `$v0` は `'a'` になり，続く read_string は `b\n` を読む．

入力バッファが持つのは，標準入力から読み込んだが消費されていない入力のみである．
標準入力に残っていてまだ読み込んでいない入力は含まない．
`StepBack` で戻した入力は入力バッファの先頭に置かれる．

### `StepBack` の挙動


| 機能                                | 取り消し                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------- |
| print_int，print_string，print_char | 出力のストリームの途中までの多バイト文字が元に戻る．出力済みの内容は消えない |
| read_int，read_char                 | `$v0` が元に戻り，消費した入力が入力バッファの先頭に戻る                     |
| read_string                         | 書き込んだ範囲(NUL を含む)のメモリが元に戻り，消費した入力も戻る             |
| exit                                | 終了状態と，出力のストリームの途中までの多バイト文字が元に戻る               |

## ランタイムエラー

ランタイムエラーは，MIPS で未定義または PlusPim が未対応の操作を検出したときに発生する．
MIPS の例外と異なり CP0 と例外ハンドラを使わず，カーネルモードでも二重例外にならない．

ランタイムエラーが発生した後は実行を続けられない．
`StepBack` によって実行前の状態に戻るか，終了すること．

### 表示

ランタイムエラーでも MIPS の例外でも，VS Code の例外ウィジェットを表示するために DAP の停止理由は `exception` とする．
両者は次の表示で区別する．

| 表示                       | ランタイムエラー                                                 | MIPS の例外                                                    |
| -------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------- |
| コールスタックの状態       | `Paused on PlusPim runtime error`                                | `Paused on MIPS exception` / `Paused on MIPS double exception` |
| 例外ウィジェットのタイトル | `PlusPim runtime error (DivisionByZero)`                         | `MIPS exception (Ov)` / `MIPS double exception (Ov)`           |
| 例外ウィジェットの本文     | 説明文と，MIPS の例外ではなく続行できないこと，`StepBack` の案内 | 説明文                                                         |
| デバッグコンソール(stderr) | 種類，アドレス，ソースの位置，説明文                             | なし                                                           |

デバッグコンソールへの出力は，たとえば次のようになり，ソースの位置へのリンクになる．

```text
[PlusPim runtime error] DivisionByZero at 0x00400010 (main.asm:12): <説明文>. Execution cannot continue; use Step Back.
```


### 発生条件

| 種類                     | 命令            | 条件                                           |
| ------------------------ | --------------- | ---------------------------------------------- |
| `DivisionByZero`         | `div`，`divu`   | `rt` が `0`                                    |
| `DivisionOverflow`       | `div`           | `rs` が `0x80000000` かつ `rt` が `0xffffffff` |
| `UnsupportedCP0Register` | `mfc0`，`mtc0`  | CP0 レジスタ番号が 8，12，13，14 以外          |
| `UnknownRuntimeCall`     | `runtime_call!` | `$v0` が 1，4，5，8，10，11，12 以外           |

- ユーザーモードの `mfc0`/`mtc0`/`runtime_call!` では，番号によらず `CpU` 例外を優先される
