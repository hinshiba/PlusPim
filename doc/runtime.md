# ランタイムドキュメント

MIPS 仕様によらない PlusPim 処理系による特別な仕様について示す．

## ランタイムコール

OSや実際のハードウェアの代わりに `runtime_call!` が最終的に入出力等のシステムコールを処理する．

引数を取らず， `$v0` レジスタの値を読み込み，値に応じた処理が実行される．
ユーザーモードで実行すると `CpU` が発生する．

### 機能一覧

| `$v0` | 機能         | 引数                                 | 結果               |
| ----- | ------------ | ------------------------------------ | ------------------ |
| 1     | print_int    | `$a0`: 整数                          | なし               |
| 4     | print_string | `$a0`: NUL 終端文字列のアドレス      | なし               |
| 5     | read_int     | なし                                 | `$v0`: 読んだ整数  |
| 8     | read_string  | `$a0`: 書き込み先，`$a1`: バッファ長 | `$a0` からのメモリ |
| 10    | exit         | なし                                 | 実行が終了する     |
| 11    | print_char   | `$a0`: 文字                          | なし               |
| 12    | read_char    | なし                                 | `$v0`: 読んだ文字  |

上記以外の番号はランタイムエラーとなる．

#### print_int (1)

`$a0` を符号付き32bit整数として10進数で出力する．
`0x80000000` は `-2147483648` と出力される．

#### print_string (4)

`$a0` が指すアドレスから NUL の直前までのバイト列を UTF-8 として出力する．

#### read_int (5)

入力から改行までの1行を読み，前後の空白を許して32bit符号付き整数として解釈した値を `$v0` に書き込む．
数値でない入力，32bit の範囲外の数，空行，EOF では `$v0` は `0` になる．
解釈に失敗した場合も，読んだ1行は消費される．

#### read_string (8)

入力から改行までの1行を読み，`$a0` から最大 `$a1 - 1` バイトと NUL を書き込む．

- 改行が収まる場合は，結果に改行を含む(SPIM/MARS と同じ)
- 入りきらなかった残りは消費されず，次の読み取りで読まれる．UTF-8 の多バイト文字は途中で切らず，収まらない文字ごと残す
- `$a1 = 1` なら NUL のみを書き込む
- `$a1 = 0` なら何も書き込まず，入力も読まない
- 入力が短い場合は，実際の入力長と NUL だけを書き込む．`$a1` が大きくても，その先のメモリは変化しない

#### exit (10)

プログラムの実行を終了する．

#### print_char (11)

`$a0` の下位1バイトを，そのコードポイント(`U+0000` から `U+00FF`)の文字として出力する．
上位のビットは無視する．
1バイトずつ1文字として扱うため，UTF-8 の多バイト文字を print_char で分割して出力することはできない．
多バイト文字は print_string を使う．

#### read_char (12)

入力から1文字だけを消費し，その文字コードを `$v0` に書き込む．
EOF では `-1`(`0xffffffff`)になる．
改行も1文字として読まれる．

### 入力バッファ

read_int，read_string，read_char は入力バッファを共有する．
ある読み取りで消費されなかった入力は失われず，次の読み取りで先頭から読まれる．
たとえば入力 `ab\n` に対して read_char を行うと `$v0` は `'a'` になり，続く read_string は `b\n` を読む．

入力バッファが持つのは，標準入力から読み込んだが消費されていない入力のみである．
標準入力に残っていてまだ読み込んでいない入力は含まない．
`StepBack` で戻した入力は入力バッファの先頭に置かれる．

### `StepBack` の挙動


| 機能                                | 取り消し                                                         |
| ----------------------------------- | ---------------------------------------------------------------- |
| print_int，print_string，print_char | 状態は変化しない．出力済みの内容は消えない                       |
| read_int，read_char                 | `$v0` が元に戻り，消費した入力が入力バッファの先頭に戻る         |
| read_string                         | 書き込んだ範囲(NUL を含む)のメモリが元に戻り，消費した入力も戻る |
| exit                                | 終了状態が解除される                                             |

## ランタイムエラー

ランタイムエラーは，MIPS で未定義または PlusPim が未対応の操作を検出したときに発生する．
MIPS の例外と異なり CP0 と例外ハンドラを使わず，カーネルモードでも二重例外にならない．

ランタイムエラーが発生した後は実行を続けられない．
`StepBack` によって実行前の状態に戻るか，終了すること．


### 発生条件

| 種類                     | 命令            | 条件                                           |
| ------------------------ | --------------- | ---------------------------------------------- |
| `DivisionByZero`         | `div`，`divu`   | `rt` が `0`                                    |
| `DivisionOverflow`       | `div`           | `rs` が `0x80000000` かつ `rt` が `0xffffffff` |
| `UnsupportedCP0Register` | `mfc0`，`mtc0`  | CP0 レジスタ番号が 8，12，13，14 以外          |
| `UnknownRuntimeCall`     | `runtime_call!` | `$v0` が 1，4，5，8，10，11，12 以外           |

- ユーザーモードの `mfc0`/`mtc0`/`runtime_call!` では，番号によらず `CpU` 例外を優先される
