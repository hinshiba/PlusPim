# 遅延スロットの振る舞い

`DelaySlots`で有効にした遅延スロットについて，`Debuggee`を1ステップずつ進めて`Core`を観測する．
分岐とロードの遅延スロットは独立に切り替わるので，それぞれ有効と無効の両方で確かめる．

## 分岐の遅延スロット

- 成立した分岐とジャンプの次の命令は，移る前に実行される．その後は分岐先へ移る
- 成立しなかった分岐の次の命令も遅延スロットであり，その後は遅延スロットの次へ進む
- 分岐を実行した後の`Core.Branch`は分岐の命令のアドレス，移る先，移り方を持つ．遅延スロットを実行すると空になる
- `jal`，`jalr`，`bgezal`，`bltzal`の戻りアドレスは命令の8バイト後である．`bltzal`と`bgezal`は不成立でも書く
- 呼び出しのフレームは遅延スロットを実行した後に積む．遅延スロットの命令は呼び出し元の深さで実行される
- 呼び出し元へのジャンプのフレームは，遅延スロットを実行した後に取り出す
- `$ra`の初期値へのジャンプは，遅延スロットを実行した後に終了する
- 遅延スロットの命令で例外が起きると，EPCと`ExceptionRaised.Epc`は分岐の命令のアドレスになり，`Cause`のBDビットが立つ．`eret`で分岐からやり直す
- 遅延スロットでない命令の例外ではBDビットは立たない
- 遅延スロットで分岐，ジャンプ，`eret`を実行すると`TransferInDelaySlot`のランタイムエラーになる．PCは遅延スロットの命令のアドレスである．遅延スロットの命令は完了していないので`Core.Branch`は残る

### 無効のとき

- 成立した分岐の次の命令は実行されない．`Core.Branch`は常に空である
- 戻りアドレスは命令の4バイト後である

## ロードの遅延スロット

- ロードの次の命令はロード先の旧値を読む．さらにその次の命令は新しい値を読む
- ロードを実行した後の`Core.Load`はロード先と値を持ち，次の命令を実行すると空になる
- ロードの次の命令がロード先へ書くと，その命令の値が残る
- `lwl`の次の`lwr`は，同じrtへ完了していない`lwl`の値と合成する(MIPS Iのバイパス)．`ulw`の展開のテストで確かめる
- ロードの次の命令で例外が起きても，ロードは完了している
- 分岐の遅延スロットのロードは，移った先の最初の命令がロードの遅延スロットになる
- ロードの次の命令が入力待ちになると，状態は変わらずロードも完了していない

### 無効のとき

- ロードの次の命令は新しい値を読む．`Core.Load`は常に空である
