# ランタイムドキュメント

MIPS仕様によらないPlusPim処理系による特別な仕様について示す．

## ランタイムコール

OSや実際のハードウェアの代わりに`runtime_call!`が最終的に入出力等のシステムコールを処理する．

引数を取らず，`$v0`レジスタの値を読み込み，値に応じた処理が実行される．
ユーザーモードで実行すると`CpU`が発生する．

`syscall`は例外としてカーネルテキストの例外ハンドラへ飛ぶので，`runtime_call!`はハンドラの中に書く．
最小のハンドラは[`samples/delay-slots/kseg.asm`](../samples/delay-slots/kseg.asm)にあり，使い方は [README](../README.md#syscallを使う場合) を参照．

### 機能一覧

| `$v0` | 機能         | 引数                                 | 結果                |
| ----- | ------------ | ------------------------------------ | ------------------- |
| 1     | print_int    | `$a0`: 整数                          | なし                |
| 4     | print_string | `$a0`: NUL 終端文字列のアドレス      | なし                |
| 5     | read_int     | なし                                 | `$v0`: 読んだ整数   |
| 8     | read_string  | `$a0`: 書き込み先，`$a1`: バッファ長 | `$a0` からのメモリ  |
| 10    | exit         | なし                                 | 実行が終了する      |
| 11    | print_char   | `$a0`: 文字                          | なし                |
| 12    | read_char    | なし                                 | `$v0`: 読んだバイト |

上記以外の番号はランタイムエラーとなる．

#### print_int (1)

`$a0`を符号付き32bit整数として10進数で出力する．
`0x80000000`は`-2147483648`と出力される．

#### print_string (4)

`$a0`が指すアドレスからNULの直前までのバイト列を出力する．
表記は出力先の符号化に依存する．

#### read_int (5)

入力から改行までの1行を読み，前後の空白を許して32bit符号付き整数として解釈した値を`$v0`に書き込む．
数値でない入力，32bitの範囲外の数，空行，EOF，ASCII範囲外の場合は`$v0`は`0`になる．
解釈に失敗した場合も，1行は消費される．

#### read_string (8)

入力から改行までの1行を読み，アドレス`$a0`を起点として最大`$a1 - 1`バイトとNULを書き込む．

- 改行が収まる場合は，結果に改行を含む
- `$a1 = 1`なら NUL のみを書き込む
- `$a1 = 0`なら何も書き込まず，入力も読まない
- 入力が短い場合は，実際の入力長とNULだけを書き込む．不足分のメモリの値は変化しない．

#### exit (10)

プログラムの実行を終了する．

#### print_char (11)

`$a0`の下位1バイトを出力する．
上位のビットは無視する．
表記は出力先の符号化に依存する．

#### read_char (12)

入力から1バイトだけを消費し，その値を`$v0`に書き込む．
EOFは`-1`(`0xffffffff`)とする．
`0xFF`のバイトは`0x000000ff`であり，EOFとは区別できる．
改行も1バイトとして読まれる．

### 巻き戻しの挙動

| 機能      | 巻き戻し                                                          |
| --------- | ----------------------------------------------------------------- |
| 出力関連  | 出力済みの内容は消えない．再実行時は出力しない．                  |
| 入力関連  | `$v0`やメモリの値は復元される．再実行時は以前の入力が用いられる． |
| exit      | 終了状態が解除される                                              |

## 遅延スロット

分岐，ジャンプ，ロードの次の命令を遅延スロットと呼ぶ．
MIPS Iに準拠して既定で有効であり，分岐とロードで別々に無効にできる．

| 種類   | 有効なとき                                   | 無効にするオプション    |
| ------ | -------------------------------------------- | ----------------------- |
| 分岐   | 遅延スロットの命令を実行してから移る         | `--no-delayed-branches` |
| ロード | 遅延スロットの命令はロード先の旧値を読む     | `--no-delayed-loads`    |

VS Codeからは`launch.json`の`"args": ["--no-delayed-branches"]`のように指定する．

### 分岐の遅延スロット

- 成立しなかった分岐の次の命令も遅延スロットとして実行する
- `jal`，`jalr`，`bgezal`，`bltzal`の戻りアドレスは命令の8バイト後になる．無効なら4バイト後
- コールスタックのフレームは，遅延スロットを実行して移った後に積む．したがって遅延スロットの命令は呼び出し元のフレームで実行される
- 遅延スロットの命令で例外が起きると，EPCは分岐の命令を指し，`Cause`のBDビット(bit 31)が立つ．`eret`で戻ると分岐からやり直す
  - EPC + 4へ戻るハンドラでは，遅延スロットの`syscall`は同じ`syscall`をやり直し続ける．`syscall`を遅延スロットに置かないこと
- 遅延スロットの分岐，ジャンプ，`eret`はMIPSで未定義なので`TransferInDelaySlot`のランタイムエラーになる
- `eret`は遅延スロットを持たない
- テキストの末尾の分岐やジャンプの遅延スロットには命令が必要である．`main`の最後の`jr $ra`の後にも`nop`を置く

### ロードの遅延スロット

- 遅延スロットの命令は，ロード先のレジスタの旧値を読む(R3000と同じ)．その次の命令からは新しい値を読む
- 遅延スロットの命令がロード先へ書くと，その命令の値が残る
- `lwl`と`lwr`は，直前の`lwl`か`lwr`の値と合成する(MIPS Iのバイパス)．`ulw`の`lwl`と`lwr`は連続してよい
- 遅延スロットの命令で例外が起きても，ロードは完了している
- 疑似命令`ulh`，`ulhu`，`ulw`の展開は，遅延スロットの有無によらず正しく動く．ただし展開の最後のロードの次の命令は，そのロードの遅延スロットである
- HIとLO，CP0のハザードは再現しない

## ランタイムエラー

ランタイムエラーは，MIPSで未定義かつエラーを通知した方がよいと思われる内容，
またはPlusPimが未対応の操作を検出したときに発生する．

この場合は実行は即座に中断され，巻き戻しか終了が必要となる．


### 発生条件

| 種類                      | 命令                                                         | 条件                                                           |
| ------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| `DivisionByZero`          | `div`，`divu`                                                | 除数`rt`が`0`                                                  |
| `UnknownRuntimeCall`      | `runtime_call!`                                              | `$v0`の値に対応するランタイムコールが存在しない                |
| `NonInstructionExecution` | 任意                                                         | 命令でない領域を実行しようとした                               |
| `TextAccess`              | ロード，ストア，`runtime_call!` の print_string，read_string | テキストかカーネルテキストのアドレスを読み書きする             |
| `TransferInDelaySlot`     | 分岐，ジャンプ，`eret`                                       | 分岐の遅延スロットで実行した                                   |
| `DoubleException`         | 任意                                                         | カーネルモードで例外の発生条件を満たす                         |

備考
- ユーザーモードの`runtime_call!`では，`CpU`例外が優先される
- print_stringはNULまでを検査する
- read_stringは書き込む範囲を検査する
